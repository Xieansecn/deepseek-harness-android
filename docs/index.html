DeepSeek Harness · Android/Termux

⚠️ 需要 Termux：本方案必须在 Android 手机的 Termux 终端 里安装运行。

这是什么

在 Android 手机上原生运行 DeepSeek Harness（@deepseek-ai/dsh，DeepSeek 官方的 agent harness，类 Claude Code）。通过 Web UI（http://127.0.0.1:3080）在手机浏览器里使用，agent 可在手机上真实执行 bash 命令。

一、安装 Termux

❗ 不要用 Google Play 版本（已过时）。官方渠道：

  • F-Droid（推荐）：f-droid.org/en/packages/com.termux
  • GitHub Releases：github.com/termux/termux-app/releases

打开 Termux 后执行 pkg update -y（可选 termux-setup-storage 授权存储）。

二、一键安装

pkg install -y git
git clone https://github.com/FunnelCakes/deepseek-harness-android.git
cd deepseek-harness-android
bash setup.sh

二·补 安装方式：npm

安装后端只有一种：npm install -g（命令与旧版逐字一致）。另有 2.5/9 pnpm 运行时供给（dsh ≥0.2.1 的插件功能运行期依赖 pnpm）。安装动作之前会先跑一次只读的 pnpm 运行时预检；它不写死 pnpm 路径、也不写死版本号：把 PATH 上每个 pnpm、~/.local/share/pnpm-pin、PNPM_HOME、npm 全局目录都探一遍并跑 --version，只认 11.x：

  • PATH 首位是可用 11.x → 直接复用，不写文件；
  • 别处有可用 11.x → 复用它（写包装指向该入口，不重新下载）；
  • 只有坏 pnpm 但 ~/bin 在 PATH 上且排在它前面 → 自动供给 11.x 并写包装压过它；
  • 实在没有可用版本且压不过 → 停止并提示（列出探测到的每个 pnpm 与版本 + 三条修复命令，明说本步骤只读未改动文件）；改完重跑 bash setup.sh 即可正常继续；
  • 包装目录不在 PATH / 别人的同名包装且不等价 → 中文提示并 exit 1（可用 DSH_PNPM_CONFLICT_OVERRIDE=1 覆盖同名包装）；
  • 历史上曾有的第二种安装方式 --pnpm 已移除：现在传 --pnpm / --npm 会报「参数已废弃」并 exit 1。
⚠️ pnpm 12 在 Android 上不可用，请只用 pnpm 11.x。另外 dsh ≥0.2.1 的插件功能（dsh plugin … / 插件市场）运行期也会从 PATH 调用 pnpm，所以插件同样依赖可用的 pnpm 11：setup.sh 的 2.5/9 步骤会自动供给（装到 ~/.local/share/pnpm-pin，并写 ~/bin/{pnpm,pn,pnpx,pnx} 包装；~/bin 必须在 PATH 中）。

三、使用

bash ~/dsh/start_dsh.sh   # 启动并自动拉起浏览器
bash ~/dsh/stop_dsh.sh    # 停止

打开 http://127.0.0.1:3080，在 Models 页面填入你的 DeepSeek API Key（存于 ~/.dsh/.credentials.yaml，0600 权限），即可开始。

五、安全说明

  • 服务只监听 127.0.0.1（本机），不走局域网。
  • API Key 存 ~/.dsh/.credentials.yaml（0600），不进日志、不进进程环境。
  • danger-full-access 关闭了进程沙箱（Android 无 bwrap/landlock 替代），agent 可执行任意命令——仅建议个人设备使用。
  • 权限层是两条：sandbox-policy.mode = danger-full-access 加 approval.policy = never。0.2.0 起新增的 permission 行按「组合后的 sandbox + approval」反查预设表，少一条就会匹配不到预设（该行不激活并报警）。
  • 升级 dsh 或 Node 后需重跑 setup.sh。

六、常见问题

  • 页面白屏/打不开：确认在 Termux 环境；看日志 ~/dsh/storage/dsh.log。
  • dsh web 报 dsh: startup failed: … listen EADDRINUSE: address already in use 127.0.0.1:3080：3080 上已经有一个 dsh web 实例（token 是进程级的，再起一个只会失败）。用 bash ~/dsh/start_dsh.sh：能复用就复用；占用端口的进程若本会话看不到（另一个用户/应用、su 启动、别的终端会话），脚本会立刻说明并给出「结束旧实例 / DSH_PORT=3081 换端口」，不再白拉起一个必然失败的实例、也不空等到超时后打开 401 页面。启动到一半就崩（profile YAML 写坏、原生绑定缺失）同样会立刻报出原因。
  • stop_dsh.sh 说「已停止」但 3080 还能打开：停止只能杀本会话可见的进程；端口仍有响应时脚本会在 stderr 提醒「占用它的进程本机看不到、不受本脚本管理」，需到启动它的窗口结束它或换 DSH_PORT。
  • 模型没反应：检查 Models 页 API Key 与 ~/.dsh/.credentials.yaml。
  • 手机上排版难受 / 软键盘挡住输入框 / 某些按钮点不动：上游 Web UI 按桌面排版所致，本方案不再注入前端代码；见「八、手机界面适配（可选）」。
  • 换机/重装：重跑 bash setup.sh。
  • 升级到 0.2.1 后首次启动，profile 里少了一个 bundle / 日志提到迁移：0.2.1 的 RETIRED_BUNDLES 迁移会自动把 dsh-experimental-schedule-bundle 从旧 profile 摘除——正常行为，不是错误，不用手动加回。
  • dsh plugin … / 插件市场报找不到 pnpm，或 pnpm 报 ERR_PNPM_STORE_DIR_ACQUIRE_OPERATION_LOCK：dsh ≥0.2.1 的插件功能运行期会从 PATH 调用 pnpm，而 pnpm 12 在 Android 上不可用。先 command -v pnpm && pnpm --version 确认解析到 11.x；需要时 npm install -g pnpm@11，或让 ~/bin/pnpm 的 11.x 包装在 PATH 中优先。
  • bash setup.sh --pnpm 报「参数已废弃」：pnpm 安装方式已移除，安装方式只有 npm install -g；直接跑 bash setup.sh（钉版本用 DSH_VERSION=<ver> bash setup.sh）。
  • 想验证「脚本本身」是否正确（不是看设备能不能用）：bash patches/verify-all-checks.sh —— 语法 + setup 静态契约 27 条 + 6 个夹具（js-patches 21 / runtime 36 / guards 39 / require-builtin 29 / profile 41 / pnpm-provision 76 断言 = 242），只读或只写临时目录，不跑 setup.sh、不碰 3080、不改安装树。想改端口就设 DSH_PORT——start_dsh.sh 会把它作为 --port 传给 dsh。
  • 单独重跑补丁脚本报 --root 相关错误：--root 是硬契约——显式给出却定位不到就退 1，不会回落到别的安装树（避免误写生产树）；不传它才自动定位。链接类补丁要 --root "$DSH_DIR/node_modules/@deepseek-ai"，平台包补丁要 --root "$DSH_DIR"。

七、作者测试环境与兼容性

  • 测试设备：华为 Mate 60（ALN-AL80），HarmonyOS 4.2.0（build 4.2.0.186），无 root，Termux（Node v26，aarch64）。
  • 实测版本：deepseek-harness 0.2.1-rc.5（撰写时的 npm latest = next，alpha 是 0.2.2-alpha.2；当前版本用 npm view @deepseek-ai/dsh version 查）。本机实跑 bash setup.sh：3m18s（npm 报 added 3 / removed 4 / changed 605 packages）、全部补丁命中（无需改锚点）、dsh web 冷启动到 token 13.9s、鉴权 303→cookie→200、日志零 warn/error；0.2.0-rc.2 与 0.1.7-rc.2 线同样通过。升级 = 重跑 bash setup.sh 后重启 GUI。
  • 0.2.1 相对 0.2.0 的变化：依赖闭包 532 → 604 包（rc.2 时点；直接依赖 +10/−6）；新增 11 个实验性 bundle、dsh-plugin-manager、dsh-plugin-market*、dsh-tool-schedule/terminal/session-query、dsh-session-query-sqlite 等，移除 dsh-webhook(-github)、dsh-hooks-codex/claude-code、dsh-tool-ralph、dsh-experimental-schedule-bundle、dsh-client-store/ui-primitives/ui-slots、dsh-invariants、dsh-hook-protocol、dsh-subagent-in-process-driver；OPTIONAL_BUNDLES 4→12（rc.2 时点，全实验性、默认关）；cordis 4.0.5、chokidar 5（需 Node ≥20.19）、openai 7.x、pi-ai 1.3；koffi/node-pty/sharp 等不变。上游 RETIRED_BUNDLES 迁移会在 0.2.1 首次启动时自动从旧 profile 摘除 dsh-experimental-schedule-bundle（正常，不是错误）。潜伏风险（默认不触发）：sherpa-onnx-node（语音输入，需手动开实验性 bundle）与 libreoffice-kit（无 android 平台包，office→pdf 可能不可用）。
  • 不同手机/ROM 差异可能导致额外问题（如部分 ROM 经 SELinux 禁用 link()、命名空间沙箱权限不同）。
  • setup.sh 覆盖通用 Android 场景，个别机型可能需额外适配。

八、手机界面适配（可选）

dsh 的 Web UI 是按桌面浏览器排的版：刘海压住顶部、软键盘盖住作曲栏、侧栏挤窄正文、个别按钮只接了 hover 路径（手指点不动）。本仓库不注入任何前端 CSS/JS（旧的注入方案依赖上游哈希类名、每次升级必漂移，已删除）。需要手机友好的界面时，可以装社区组合包插件 Xieansecn/dsh-android-ui（官方插件形态，不改 dsh 产品文件）：

dsh plugin --profile web add github:Xieansecn/dsh-android-ui
dsh --profile web --dump-config | grep -A2 dsh-android-ui   # 应出现 "# == dsh-android-ui"
bash ~/dsh/restart_dsh_now.sh                              # Node 半在启动时读进内存，必须重启

卸载：dsh plugin --profile web remove dsh-android-ui，然后同样重启。

它做的事：viewport 改为 viewport-fit=cover + interactive-widget=resizes-content（刘海避让，软键盘收缩内容区）、侧栏变抽屉、safe-area 与作曲栏重排、启动前 polyfill（AbortSignal.any / crypto.randomUUID）、运行期软键盘跟随与触摸兜底。

⚠️ 注意事项：这是第三方插件，不属于本项目；它按 dsh 0.1.7-rc.2 核对了上游哈希类名，上游改版会静默失效（页面正常、效果全无），升级 dsh 后请同步升级/重装，或先卸载以确认问题归属；「普通回车=换行」不在该插件内，仍由本仓库 setup.sh 修补；重跑 setup.sh 不会破坏它（权限层按内容分类合并：dsh 的空数组模板会整体替换、已有配置层才追加）；鉴权链路不变，仍用 start_dsh.sh 打开带 token 的 URL。

What is this

Run DeepSeek Harness (@deepseek-ai/dsh, DeepSeek's official agent harness, Claude Code–like) natively on Android. Use it through the Web UI at http://127.0.0.1:3080 in your mobile browser; the agent can run real bash commands on the phone.

  • GitHub Releases: github.com/termux/termux-app/releases

2. One-click setup

pkg install -y git
git clone https://github.com/FunnelCakes/deepseek-harness-android.git
cd deepseek-harness-android
bash setup.sh

2.1 Install backend: npm

There is exactly one backend: npm install -g (the command is byte-for-byte unchanged). A separate 2.5/9 pnpm runtime provisioning step remains because dsh ≥0.2.1's plugin features depend on pnpm at runtime. A read-only pnpm runtime preflight runs before any install action; it hardcodes neither a pnpm path nor a version — it probes every pnpm on PATH, ~/.local/share/pnpm-pin, PNPM_HOME and the npm global dir, running --version on each, and accepts 11.x only:

  • a working 11.x first on PATH → reused, nothing written;
  • a working 11.x elsewhere → reused (wrappers point at it, nothing downloaded);
  • only a broken pnpm, but ~/bin is on PATH ahead of it → provisions 11.x and shadows it;
  • no usable version and no way to shadow → stops with a diagnosis (every pnpm found + version + three fixes; states the step is read-only); re-running bash setup.sh after the fix just works;
  • wrapper dir not on PATH / someone else's non-equivalent wrapper → Chinese remediation and exit 1 (force with DSH_PNPM_CONFLICT_OVERRIDE=1);
  • the old second backend --pnpm was removed: --pnpm / --npm now report "deprecated flag" and exit 1.
⚠️ pnpm 12 does not work on Android — use pnpm 11.x only. Also, dsh ≥0.2.1's plugin features (dsh plugin … / plugin market) shell out to pnpm from PATH at runtime, so plugins need a working pnpm 11 too: the 2.5/9 step of setup.sh provisions it automatically (installed under ~/.local/share/pnpm-pin plus ~/bin/{pnpm,pn,pnpx,pnx} wrappers; ~/bin must be on PATH).

3. Usage

bash ~/dsh/start_dsh.sh   # start & auto-open browser
bash ~/dsh/stop_dsh.sh    # stop

Open http://127.0.0.1:3080, enter your DeepSeek API Key in the Models page (stored at ~/.dsh/.credentials.yaml, mode 0600), and start chatting.

5. Security notes

  • The service listens only on 127.0.0.1 (local, not LAN).
  • API Key is stored at ~/.dsh/.credentials.yaml (0600), never in logs or process env.
  • danger-full-access disables the process sandbox (no bwrap/landlock on Android); the agent can run any command — personal devices only.
  • The permission layer is two entries: sandbox-policy.mode = danger-full-access plus approval.policy = never. The 0.2.0-only permission row derives a preset from that composed pair, so a missing half matches no preset (the row refuses to activate and warns).
  • Re-run setup.sh after upgrading dsh or Node.

6. FAQ

  • Blank screen / cannot open: make sure it's Termux; check ~/dsh/storage/dsh.log.
  • dsh web prints dsh: startup failed: … listen EADDRINUSE: address already in use 127.0.0.1:3080: another dsh web instance already owns 3080 (tokens are per-process, so a second instance can only fail). Use bash ~/dsh/start_dsh.sh: it reuses the running instance; if the process holding the port is invisible to this session (another user/app, started under su, another terminal session) it immediately explains and offers "stop the old instance / DSH_PORT=3081" instead of spawning a doomed instance and waiting out the timeout before opening a 401 page. Boot failures (broken profile YAML, missing native binding) are reported immediately too.
  • stop_dsh.sh says "stopped" but 3080 still opens: stop can only kill processes visible to this session; when the port still responds the script warns on stderr that the holder is invisible and unmanaged — end it in the window that started it, or use another DSH_PORT.
  • Model not responding: check the API Key in Models page and ~/.dsh/.credentials.yaml.
  • Awkward phone layout / the soft keyboard hides the input / some buttons ignore taps: that is upstream's desktop-oriented Web UI and this project no longer injects front-end code; see "8. Mobile UI (optional)".
  • Reinstall / new device: re-run bash setup.sh.
  • After upgrading to 0.2.1 the profile lost a bundle / the log mentions a migration: 0.2.1's RETIRED_BUNDLES migration auto-removes dsh-experimental-schedule-bundle from existing profiles — normal behaviour, not an error; do not add it back.
  • dsh plugin … / plugin market cannot find pnpm, or pnpm reports ERR_PNPM_STORE_DIR_ACQUIRE_OPERATION_LOCK: since 0.2.1 the plugin features shell out to pnpm from PATH, and pnpm 12 does not work on Android. Check command -v pnpm && pnpm --version resolves to 11.x; use npm install -g pnpm@11 or make the 11.x wrapper at ~/bin/pnpm take precedence in PATH.
  • bash setup.sh --pnpm reports "deprecated flag": the pnpm install backend is gone; npm install -g is the only backend. Just run bash setup.sh (pin a version with DSH_VERSION=<ver> bash setup.sh).
  • Want to verify the scripts themselves (not just that the device works): bash patches/verify-all-checks.sh — syntax + 27 setup static contracts + 6 fixtures (js-patches 21 / runtime 36 / guards 39 / require-builtin 29 / profile 41 / pnpm-provision 76 assertions = 242), read-only or temp-dir only: never runs setup.sh, never touches port 3080, never modifies the install tree. To change the port set DSH_PORT — start_dsh.sh passes it to dsh as --port.
  • Re-running one patch script fails with a --root error: --root is a hard contract — if given explicitly and it does not resolve, the script exits 1 and never falls back to another install tree (so a temp-copy test can't write the production tree); auto-location only happens without --root. Link patches want --root "$DSH_DIR/node_modules/@deepseek-ai", the platform-package patch wants --root "$DSH_DIR".

8. Mobile UI (optional)

dsh's Web UI is laid out for desktop browsers: the notch covers the top, the soft keyboard hides the composer, the sidebar squeezes the text, and a few buttons are wired to hover only. This repo injects no front-end CSS/JS (the old injection scheme keyed off upstream hashed class names and drifted on every upgrade, so it was deleted). For a phone-friendly UI, install the community composition-package plugin Xieansecn/dsh-android-ui (an official plugin; it touches no dsh product file):

dsh plugin --profile web add github:Xieansecn/dsh-android-ui
dsh --profile web --dump-config | grep -A2 dsh-android-ui   # expect "# == dsh-android-ui"
bash ~/dsh/restart_dsh_now.sh                              # the Node half is read at boot: restart required

Uninstall: dsh plugin --profile web remove dsh-android-ui, then restart the same way.

What it does: rewrites viewport to viewport-fit=cover + interactive-widget=resizes-content (notch avoidance, IME shrinks the content area), turns the sidebar into a drawer, safe-area padding and composer recomposition, boot-time polyfills (AbortSignal.any / crypto.randomUUID), plus runtime keyboard following and touch fallbacks.

⚠️ Notes: this is a third-party plugin, not part of this project; its hashed class names were verified against dsh 0.1.7-rc.2 and fail silently when upstream changes them (page fine, effects gone), so upgrade/reinstall it after a dsh upgrade — or uninstall it first to attribute the problem. "Enter = newline" is not in that plugin; this repo's setup.sh still patches it. Re-running setup.sh will not break it (the permission layer is merged by content: dsh's empty-array template is replaced, existing layers are appended to). The auth chain is unchanged: keep opening the tokenized URL via start_dsh.sh.
