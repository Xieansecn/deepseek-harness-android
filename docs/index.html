DeepSeek Harness · Android/Termux

⚠️ 需要 Termux：本方案必须在 Android 手机的 Termux 终端 里安装运行。

这是什么

在 Android 手机上原生运行 DeepSeek Harness（@deepseek-ai/dsh，DeepSeek 官方的 agent harness，类 Claude Code）。通过 Web UI（http://127.0.0.1:3080）在手机浏览器里使用，agent 可在手机上真实执行 bash 命令。

一、安装 Termux

❗ 不要用 Google Play 版本（已过时）。官方渠道：

  • F-Droid（推荐）：f-droid.org/en/packages/com.termux
  • GitHub Releases：github.com/termux/termux-app/releases

打开 Termux 后执行 pkg update -y（可选 termux-setup-storage 授权存储）。

二、一键安装

pkg install -y git
git clone https://github.com/FunnelCakes/deepseek-harness-android.git
cd deepseek-harness-android
bash setup.sh

三、使用

bash ~/dsh/start_dsh.sh   # 启动并自动拉起浏览器
bash ~/dsh/stop_dsh.sh    # 停止

打开 http://127.0.0.1:3080，在 Models 页面填入你的 DeepSeek API Key（存于 ~/.dsh/.credentials.yaml，0600 权限），即可开始。

五、安全说明

  • 服务只监听 127.0.0.1（本机），不走局域网。
  • API Key 存 ~/.dsh/.credentials.yaml（0600），不进日志、不进进程环境。
  • danger-full-access 关闭了进程沙箱（Android 无 bwrap/landlock 替代），agent 可执行任意命令——仅建议个人设备使用。
  • 权限层是两条：sandbox-policy.mode = danger-full-access 加 approval.policy = never。0.2.0 起新增的 permission 行按「组合后的 sandbox + approval」反查预设表，少一条就会匹配不到预设（该行不激活并报警）。
  • 升级 dsh 或 Node 后需重跑 setup.sh。

六、常见问题

  • 页面白屏/打不开：确认在 Termux 环境；看日志 ~/dsh/storage/dsh.log。
  • 模型没反应：检查 Models 页 API Key 与 ~/.dsh/.credentials.yaml。
  • 手机上排版难受 / 软键盘挡住输入框 / 某些按钮点不动：上游 Web UI 按桌面排版所致，本方案不再注入前端代码；见「八、手机界面适配（可选）」。
  • 换机/重装：重跑 bash setup.sh。

七、作者测试环境与兼容性

  • 测试设备：华为 Mate 60（ALN-AL80），HarmonyOS 4.2.0（build 4.2.0.186），无 root，Termux（Node v26，aarch64）。
  • 实测版本：deepseek-harness 0.2.0-rc.2（撰写时的 npm latest = next；当前版本用 npm view @deepseek-ai/dsh version 查）。实测：完整安装、全部补丁、dsh web 冷启动到 token 7~13s、鉴权 303→cookie→200、日志零 warn/error；0.1.7-rc.2 线同样通过。
  • 不同手机/ROM 差异可能导致额外问题（如部分 ROM 经 SELinux 禁用 link()、命名空间沙箱权限不同）。
  • setup.sh 覆盖通用 Android 场景，个别机型可能需额外适配。

欢迎提 issue / PR 适配更多环境：Issues 或 Pull Request 均可。

八、手机界面适配（可选）

dsh 的 Web UI 是按桌面浏览器排的版：刘海压住顶部、软键盘盖住作曲栏、侧栏挤窄正文、个别按钮只接了 hover 路径（手指点不动）。本仓库不注入任何前端 CSS/JS（旧的注入方案依赖上游哈希类名、每次升级必漂移，已删除）。需要手机友好的界面时，可以装社区组合包插件 Xieansecn/dsh-android-ui（官方插件形态，不改 dsh 产品文件）：

dsh plugin --profile web add github:Xieansecn/dsh-android-ui
dsh --profile web --dump-config | grep -A2 dsh-android-ui   # 应出现 "# == dsh-android-ui"
bash ~/dsh/restart_dsh_now.sh                              # Node 半在启动时读进内存，必须重启

卸载：dsh plugin --profile web remove dsh-android-ui，然后同样重启。

它做的事：viewport 改为 viewport-fit=cover + interactive-widget=resizes-content（刘海避让，软键盘收缩内容区）、侧栏变抽屉、safe-area 与作曲栏重排、启动前 polyfill（AbortSignal.any / crypto.randomUUID）、运行期软键盘跟随与触摸兜底。

⚠️ 注意事项：这是第三方插件，不属于本项目；它按 dsh 0.1.7-rc.2 核对了上游哈希类名，上游改版会静默失效（页面正常、效果全无），升级 dsh 后请同步升级/重装，或先卸载以确认问题归属；「普通回车=换行」不在该插件内，仍由本仓库 setup.sh 修补；重跑 setup.sh 不会破坏它（权限层按内容分类合并：dsh 的空数组模板会整体替换、已有配置层才追加）；鉴权链路不变，仍用 start_dsh.sh 打开带 token 的 URL。

What is this

Run DeepSeek Harness (@deepseek-ai/dsh, DeepSeek's official agent harness, Claude Code–like) natively on Android. Use it through the Web UI at http://127.0.0.1:3080 in your mobile browser; the agent can run real bash commands on the phone.

1. Install Termux

❗ Do NOT use the Google Play version (outdated). Official sources:

  • F-Droid (recommended): f-droid.org/en/packages/com.termux
  • GitHub Releases: github.com/termux/termux-app/releases

After opening Termux, run pkg update -y (optionally termux-setup-storage).

2. One-click setup

pkg install -y git
git clone https://github.com/FunnelCakes/deepseek-harness-android.git
cd deepseek-harness-android
bash setup.sh

3. Usage

bash ~/dsh/start_dsh.sh   # start & auto-open browser
bash ~/dsh/stop_dsh.sh    # stop

Open http://127.0.0.1:3080, enter your DeepSeek API Key in the Models page (stored at ~/.dsh/.credentials.yaml, mode 0600), and start chatting.

5. Security notes

  • The service listens only on 127.0.0.1 (local, not LAN).
  • API Key is stored at ~/.dsh/.credentials.yaml (0600), never in logs or process env.
  • danger-full-access disables the process sandbox (no bwrap/landlock on Android); the agent can run any command — personal devices only.
  • The permission layer is two entries: sandbox-policy.mode = danger-full-access plus approval.policy = never. The 0.2.0-only permission row derives a preset from that composed pair, so a missing half matches no preset (the row refuses to activate and warns).
  • Re-run setup.sh after upgrading dsh or Node.

6. FAQ

  • Blank screen / cannot open: make sure it's Termux; check ~/dsh/storage/dsh.log.
  • Model not responding: check the API Key in Models page and ~/.dsh/.credentials.yaml.
  • Awkward phone layout / the soft keyboard hides the input / some buttons ignore taps: that is upstream's desktop-oriented Web UI and this project no longer injects front-end code; see "8. Mobile UI (optional)".
  • Reinstall / new device: re-run bash setup.sh.

7. Author's test environment & compatibility

  • Tested device: Huawei Mate 60 (ALN-AL80), HarmonyOS 4.2.0 (build 4.2.0.186), no root, Termux (Node v26, aarch64).
  • Tested version: deepseek-harness 0.2.0-rc.2 (the npm latest = next at the time of writing; check the current one with npm view @deepseek-ai/dsh version). Verified: full install, every patch, dsh web cold start to token in 7–13s, auth 303→cookie→200, zero warn/error lines; the 0.1.7-rc.2 line passes too.
  • Different phones/ROMs may behave differently (e.g. some ROMs block link() via SELinux, namespace-sandbox permissions vary).
  • setup.sh covers common Android cases; specific devices may need extra tweaks.

Issues & PRs welcome: Issues or pull requests for your environment.

8. Mobile UI (optional)

dsh's Web UI is laid out for desktop browsers: the notch covers the top, the soft keyboard hides the composer, the sidebar squeezes the text, and a few buttons are wired to hover only. This repo injects no front-end CSS/JS (the old injection scheme keyed off upstream hashed class names and drifted on every upgrade, so it was deleted). For a phone-friendly UI, install the community composition-package plugin Xieansecn/dsh-android-ui (an official plugin; it touches no dsh product file):

dsh plugin --profile web add github:Xieansecn/dsh-android-ui
dsh --profile web --dump-config | grep -A2 dsh-android-ui   # expect "# == dsh-android-ui"
bash ~/dsh/restart_dsh_now.sh                              # the Node half is read at boot: restart required

Uninstall: dsh plugin --profile web remove dsh-android-ui, then restart the same way.

What it does: rewrites viewport to viewport-fit=cover + interactive-widget=resizes-content (notch avoidance, IME shrinks the content area), turns the sidebar into a drawer, safe-area padding and composer recomposition, boot-time polyfills (AbortSignal.any / crypto.randomUUID), plus runtime keyboard following and touch fallbacks.

⚠️ Notes: this is a third-party plugin, not part of this project; its hashed class names were verified against dsh 0.1.7-rc.2 and fail silently when upstream changes them (page fine, effects gone), so upgrade/reinstall it after a dsh upgrade — or uninstall it first to attribute the problem. "Enter = newline" is not in that plugin; this repo's setup.sh still patches it. Re-running setup.sh will not break it (the permission layer is merged by content: dsh's empty-array template is replaced, existing layers are appended to). The auth chain is unchanged: keep opening the tokenized URL via start_dsh.sh.
