1快速开始

pkg update && pkg upgrade -y
pkg install -y git

4配置

变量默认作用
DSH_PORT3080端口，脚本显式转成 dsh 的 --port
DSH_VERSION空钉版本（灰度/回退），如 0.2.2-rc.5
DSH_ORIGIN127.0.0.1交给浏览器的 origin（localhost 可绕开 PWA 丢 token）
DSH_NO_OPEN空只拉起服务，不打开浏览器
DSH_VIA_APPmark.via优先使用的浏览器包名
NO_COLOR空关闭彩色输出
完整变量表（含停止梯子与调试项）
  • DSH_READY_TIMEOUT（90）：等带 token URL 的最长秒数
  • DSH_STOP_GRACE / DSH_STOP_TIMEOUT（1.5 / 6）：优雅窗口 → 补发 SIGTERM → SIGKILL
  • DSH_WEB_PATTERN：多安装并存时的进程匹配模式
  • DSH_OPEN_APP / DSH_OPEN_CHOOSER：指定浏览器 / 弹出选择器
  • SETUP_VERBOSE：等同 --verbose

5常见问题

  • bad interpreter: /usr/bin/env：Termux 上 /usr/bin 不可解析；本仓库一律用 Termux 绝对 shebang。
  • EADDRINUSE：端口上已有实例；start 脚本先探端口，提示换 DSH_PORT=3081。
  • koffi 被跳过：它在 SKIP_SCRIPTS 里（进白名单会让 npm 12 整次安装退 1），运行期只在 win32 用到。
  • 能用 pnpm 吗：不能，符号链接 store 会破坏补丁落点，且默认拦截 node-pty 构建。
  • setup.sh 停在 4/8：平台包与 ripgrep 是硬阻断，按提示看 ~/dsh/setup.log。

6安全

  • danger-full-access 等于关闭进程沙箱：Android 无 bwrap/landlock，仅建议个人设备。
  • 服务只监听 127.0.0.1，不走局域网。
  • API Key 与 cookie 签名 secret 存于 ~/.dsh（0600）。

5FAQ

  • bad interpreter: /usr/bin/env — /usr/bin is unresolvable on Termux; every script uses a Termux absolute shebang.
  • EADDRINUSE — an instance already listens; the start script probes first and suggests DSH_PORT=3081.
  • koffi skipped — it sits in SKIP_SCRIPTS (allowlisting fails the whole install under npm 12) and is only loaded on win32.
  • pnpm? — not supported: the symlinked store breaks patch placement and blocks the node-pty build.
  • setup.sh stops at 4/8 — the platform package and ripgrep fix are hard blockers; see ~/dsh/setup.log.

6Security

  • danger-full-access disables the process sandbox (Android has no bwrap/landlock) — personal devices only.
  • Listens on 127.0.0.1 only.
  • API keys and the cookie secret live in ~/.dsh (0600).
