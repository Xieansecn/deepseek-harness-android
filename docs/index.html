DeepSeek Harness · Android/Termux

⚠️ 需要 Termux：本方案必须在 Android 手机的 Termux 终端 里安装运行。
仓库定位：只有安装期补丁，只服务 Termux/Android，不改动 dsh 前端。

这是什么

在 Android 手机上原生运行 DeepSeek Harness（@deepseek-ai/dsh，DeepSeek 官方的 agent harness）。通过 Web UI（http://127.0.0.1:3080）在手机浏览器里使用，agent 可在手机上真实执行 bash 命令。

本仓库负责：npm install -g 装上游 dsh → 对已安装的那份文件打 8 项 Android 兼容补丁 → 提供启动/停止脚本与权限层。

一、安装 Termux 与依赖

❗ 不要用 Google Play 版本（已过时）。官方渠道：F-Droid 或 GitHub Releases。

pkg update && pkg upgrade -y
pkg install -y git
# setup.sh 会自动安装 cmake clang make binutils pkg-config python nodejs ripgrep

二、一键安装

git clone <本仓库> deepseek-harness-android
cd deepseek-harness-android
bash setup.sh          # 安装 dsh + 全部兼容补丁（5～15 分钟）

安装方式只有 npm（npm install -g @deepseek-ai/dsh）。--pnpm / --npm 参数已废弃；不要用 pnpm 安装（符号链接布局会破坏补丁落点，且 pnpm 默认拦截 node-pty 构建）。

三、启动与使用

bash ~/dsh/start_dsh.sh      # 启动并打开带 token 的浏览器
bash ~/dsh/stop_dsh.sh       # 停止
bash ~/dsh/restart_dsh_now.sh

开始使用前，在 Web UI 的 Models 页面填写 DeepSeek API Key。

四、setup.sh 自动修复的 Android 兼容问题

问题做法
启动即崩：No usable native binding found for node-addon-require-builtin-android-arm64生成纯 JS 平台包，dsh 包装脚本带 --expose-internals
终端不可用：terminal inspection is unsupported on platform androiddsh-subprocess-local 视 android 为 linux

不做的事：不改前端、不注入 CSS/JS、不做性能补丁。

五、安全说明

  • danger-full-access 等于关闭进程沙箱：Android 无 bwrap/landlock，受限模式会让 bash 工具直接不可用。仅建议个人设备。
  • 服务只监听 127.0.0.1，不走局域网。
  • API Key 与 cookie 签名 secret 存于 ~/.dsh（0600）。

六、常见问题

  • bad interpreter: /usr/bin/env：Termux 上 /usr/bin 不可解析，本仓库一律用 Termux 绝对 shebang。
  • EADDRINUSE：端口上已有实例；start_dsh.sh 会先探端口，提示换 DSH_PORT=3081。
  • koffi 被跳过：它在 SKIP_SCRIPTS 里（npm 12 下放进白名单会让整次安装退 1），运行期只走 win32 分支，Android 用不到。
  • 升级 / 修复：只走 bash setup.sh；直接 npm -g update 会覆盖补丁。

七、测试环境

Huawei Mate 60（HarmonyOS 4.2，无 root），Termux aarch64，Node v26.13，npm 12.x，ripgrep 15.2.0。版本基线：0.2.2-rc.5（npm latest），并继续支持 rc.1 / rc.3。

What is this

Run DeepSeek Harness (@deepseek-ai/dsh) natively on Android via Termux, and use it from the phone browser at http://127.0.0.1:3080.

This repository installs upstream with npm install -g, patches the installed tree with eight Android compatibility fixes, and ships start/stop scripts plus the permission layer.

1. Install Termux and dependencies

Do not use the Google Play build. Use F-Droid or GitHub Releases.

pkg update && pkg upgrade -y
pkg install -y git
# setup.sh installs cmake clang make binutils pkg-config python nodejs ripgrep

2. One-command setup

git clone <this repo> deepseek-harness-android
cd deepseek-harness-android
bash setup.sh          # 5–15 minutes

npm is the only installer. --pnpm / --npm are retired, and pnpm is not supported (its symlinked store breaks patch placement and it blocks the node-pty build).

3. Start and use

bash ~/dsh/start_dsh.sh      # opens the token URL
bash ~/dsh/stop_dsh.sh
bash ~/dsh/restart_dsh_now.sh

Fill in your DeepSeek API key on the Models page of the web UI.

4. What setup.sh fixes

SymptomFix
Boot fails: No usable native binding found for node-addon-require-builtin-android-arm64generate the platform package (pure JS) + --expose-internals wrapper
terminal inspection is unsupported on platform androidtreat android as linux in dsh-subprocess-local
node-pty has no Android prebuildallow its build script and compile against Termux headers
ripgrep launch failedsymlink system rg into the ripgrep platform package + source fallback
EACCES ... link on sessions/attachments/writerename / "O_EXCL placeholder + rename" instead of hard links
flock is not supported on android-arm64compile flock.c into a local system.node
sharp cannot load on android-arm64install the matching @img/sharp-wasm32 + @emnapi/runtime
bash tool throws SANDBOX_UNAVAILABLEwrite the danger-full-access + approval: never layer

Not done: no frontend edits, no CSS/JS injection, no performance patches.

5. Security notes

  • danger-full-access disables the process sandbox (Android has no bwrap/landlock). Personal devices only.
  • Listens on 127.0.0.1 only.
  • API keys and the cookie secret live in ~/.dsh with mode 0600.

6. FAQ

  • bad interpreter: /usr/bin/env — /usr/bin is unresolvable on Termux; all scripts use Termux absolute shebangs.
  • EADDRINUSE — an instance already listens on the port; the start script detects it and suggests DSH_PORT=3081.
  • koffi skipped — it is in SKIP_SCRIPTS (under npm 12 putting it in the allowlist fails the whole install) and dsh only loads it on win32.
  • Upgrade/repair — always bash setup.sh; npm -g update wipes the patches.

7. Tested environment

Huawei Mate 60 (HarmonyOS 4.2, no root), Termux aarch64, Node v26.13, npm 12.x, ripgrep 15.2.0. Baseline 0.2.2-rc.5 (npm latest); rc.1 / rc.3 remain supported.
